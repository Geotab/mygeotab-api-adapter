## Upgrading to v5.1.0.0

> **WARNING!** The upgrade instructions provided in this document only apply to Geotab DIG Adapter version **5.0.0.3**. If upgrading from an earlier version, after downloading the latest application executable package(s), it is necessary to FIRST follow the instructions and any associated guides in the [Change Log](../../CHANGELOG.md) for each successive version up to and including v5.0.0.3 and THEN follow the instructions below.

Version 5.1.0.0 completes the DIG API re-authentication fix that began in version 5.0.0.3. Version 5.0.0.3 corrected the handling of a rejected bearer token on record-posting calls; version 5.1.0.0 applies the same correction to the token *refresh* call. Previously, if the DIG API rejected the adapter's refresh token with a `401 Unauthorized` or `403 Forbidden` response, the adapter retried that dead refresh token instead of escalating to a full re-login — again silently halting all delivery of records to MyGeotab until the adapter was manually restarted. The adapter now performs a full re-authentication automatically in this situation.

There are **no database schema or configuration file changes in version 5.1.0.0**. Existing `appsettings.json` and `nlog.config` files do not need to be modified.

**Existing v5.0.0.3 installations are recommended to upgrade** to obtain this fix.

### 1 Download

Download the application following the [Download](../../README.md#12-download) instructions in the README.

### 2 Stop Application

Stop the Geotab DIG Adapter if it is running.

### 3 Backup Configuration Files

Backup the existing `appsettings.json` and `nlog.config` files (to keep track of the existing setting values).

### 4 Deploy Application

Replace the existing v5.0.0.3 application files with the new v5.1.0.0 application files. Restore the existing `appsettings.json` and `nlog.config` files (backed-up in [Step 3](#3-backup-configuration-files)) by copying them over the new ones — they do not need to be modified.

### 5 Start Application

Start the Geotab DIG Adapter application and monitor it and its logs for several minutes to ensure that it is working properly, indicating that the upgrade was successful.
