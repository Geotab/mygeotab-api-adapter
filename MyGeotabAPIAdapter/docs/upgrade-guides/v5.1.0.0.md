## Upgrading to v5.1.0.0

> **WARNING!** The upgrade instructions provided in this document only apply to MyGeotab API Adapter version **5.0.0.3**. If upgrading from an earlier version, after downloading the latest application executable package(s), it is necessary to FIRST follow the instructions and any associated guides in the [Change Log](../../CHANGELOG.md) for each successive version up to and including v5.0.0.3 and THEN follow the instructions below.

> **This is a schema-changing upgrade.** Version 5.1.0.0 adds the `ShipmentLogs2` and `stg_ShipmentLogs2` tables and the `spMerge_stg_ShipmentLogs2` stored procedure/function to the adapter database, and adds a `ShipmentLog` section to `appsettings.json`. A database upgrade script **must** be run (see [Step 4](#4-upgrade-adapter-database)).

Fully-detailed instructions for deploying the MyGeotab API Adapter solution to a **new environment** are provided in the [README](../../README.md) (see [Section 1 Quick Start Guide](../../README.md#1-quick-start-guide)).

To upgrade an **existing environment** in which version **5.0.0.3** of the MyGeotab API Adapter is already deployed, follow the steps in the sections below.

### 1 Download

Download the application and database scripts following the [Download](../../README.md#12-download) instructions in the README.

### 2 Stop Application

Stop the MyGeotab API Adapter if it is running.

### 3 Backup Configuration Files

Backup the existing `appsettings.json` and `nlog.config` files (to keep track of the existing setting values).

### 4 Upgrade Adapter Database

This release **adds new objects to the adapter database** (the `ShipmentLogs2` partitioned table, the `stg_ShipmentLogs2` staging table, and the `spMerge_stg_ShipmentLogs2` stored procedure/function) and updates the database version from 5.0.0.0 to 5.1.0.0.

Run the appropriate upgrade script for your database provider:

**SQL Server:**

```sql
-- Execute the upgrade script against the adapter database:
MSSQL_5.1.0.0_ShipmentLogs.sql
```

**PostgreSQL:**

```sql
-- Execute the upgrade script against the adapter database:
PG_5.1.0.0_ShipmentLogs.sql
```

**Verify the upgrade:**

```sql
-- SQL Server:
SELECT * FROM dbo.MiddlewareVersionInfo2 WITH (NOLOCK) ORDER BY RecordCreationTimeUtc DESC;

-- PostgreSQL:
SELECT * FROM "MiddlewareVersionInfo2" ORDER BY "RecordCreationTimeUtc" DESC;
```

The most recent row should show `DatabaseVersion` = `5.1.0.0`.

### 5 Deploy and Configure Application

This step is essentially [Step 2: Install](../../README.md#12-download) and [Step 3: Configure](../../README.md#14-deploy-and-configure-the-application) in the README. The existing folder containing the earlier version of the application can be backed-up and replaced with this new one, or this new one can be located alongside the old one with the old one serving as a backup.

#### appsettings.json

A new `ShipmentLog` section has been added to the `Feeds` configuration in version 5.1.0.0:

```json
"ShipmentLog": {
  "EnableShipmentLogFeed": false,
  "ShipmentLogFeedIntervalSeconds": 10
}
```

- `EnableShipmentLogFeed` — enables or disables the ShipmentLog feed. It is **disabled by default** (`false`). Set it to `true` to have the adapter pull ShipmentLog records from MyGeotab.
- `ShipmentLogFeedIntervalSeconds` — the minimum number of seconds to wait between `GetFeed<ShipmentLog>` calls.

One option is to simply use the new `appsettings.json` file and update the values of all settings as desired. Another option is to use your already populated version 5.0.0.3 one and add the `ShipmentLog` section shown above to the `Feeds` section. For the latter option, overwrite the new `appsettings.json` file with the version 5.0.0.3 one that was backed-up in [Step 3](#3-backup-configuration-files) and then add the `ShipmentLog` section.

#### nlog.config

No changes were made to `nlog.config` in version 5.1.0.0. If any customizations were made to the file, it is possible to simply overwrite the new `nlog.config` file with the version 5.0.0.3 one that was backed-up in [Step 3](#3-backup-configuration-files).

### 6 Start Application

Start the MyGeotab API Adapter application and monitor it and its logs for several minutes to ensure that it is working properly, indicating that the upgrade was successful.

If the ShipmentLog feed was enabled, confirm that a `ShipmentLogProcessor2` row appears in the `OServiceTracking2` table and that records begin to populate the `ShipmentLogs2` table.
